# 系统表与启动初始化

## 模块目标

系统表负责承载数据库自身运行所需的元数据和管理信息，例如：

- 用户与权限
- 系统库对象
- 时区、帮助表等辅助信息

启动初始化则负责首次部署和后续升级中的系统库准备。

## 如果你自己实现，应该怎么抽象

建议把“系统表结构”和“初始化器”分开：

- `BootstrapDDL`: 首次创建系统表
- `BootstrapData`: 初始数据灌入
- `UpgradeDDL`: 升级时变更系统表结构

## 核心数据结构

- `BootstrapStep`
- `SystemTableDef`
- `PrivilegeCache`
- `TimezoneCatalog`

## 关键流程

1. 检测数据目录是否已初始化
2. 若未初始化，则创建系统库与系统表
3. 灌入基础系统数据
4. 启动时加载权限缓存与其他系统缓存
5. 版本升级时执行系统表修复或迁移

## 工程实现建议

- 初始化器必须可重入或至少可检测“已初始化”状态。
- 系统表版本要明确记录，升级脚本必须基于版本推进。
- 权限缓存和系统表存储要解耦；前台鉴权应主要依赖缓存而不是频繁扫表。

## 最小可用版本

- 用户权限表
- 系统 schema 初始化

- 系统表版本标识
