# 进程模型与启动流程

## 模块目标

这个模块负责把数据库从“一个二进制程序”变成“一个可持续运行的服务进程”。它要解决：

- 配置如何加载
- 全局模块如何初始化
- 存储引擎、系统表、后台线程如何启动
- 服务何时开始对外接收连接
- 关闭和异常退出时如何回收资源

## 当前仓库参照实现

关键入口和参照文件：

- `sql/main.cc`: `main()` 只转调 `mysqld_main()`
- `sql/mysqld.cc`: 服务启动、全局初始化、网络初始化、后台线程启动、对外监听
- `scripts/mysql_install_db.pl.in`, `scripts/mysql_system_tables.sql`: 首次启动前后的初始化脚本
- `support-files/mysql.server.sh`, `scripts/mysqld_safe.sh`: 服务进程封装与守护

从当前仓库可见，`mysqld_main()` 的顺序大致是：基础库初始化、读取配置、系统变量初始化、插件与服务组件初始化、网络与 SSL 初始化、权限与系统表初始化、后台线程启动、监听连接。

## 如果你自己实现，应该怎么抽象

建议把启动流程拆成 5 层：

1. `BootstrapRuntime`
负责进程级基础设施，例如配置、日志、时钟、线程库、信号处理。

2. `GlobalCatalogBootstrap`
负责打开数据目录、加载系统表、恢复元数据缓存、恢复存储引擎。

3. `StorageBootstrap`
负责 buffer pool、redo、undo、checkpoint、后台刷盘线程、purge 线程等。

4. `SQLBootstrap`
负责系统变量、函数注册、字符集、权限缓存、统计信息、计划缓存等。

5. `ListenerBootstrap`
负责网络监听、协议线程池或连接线程模型、对外 ready 状态。

核心原则是：只有在前四层全部成功后，监听层才开始 accept 连接。

- `CatalogCache`
- `BackgroundTaskManager`
- `ListenerManager`

## 关键流程

1. 初始化进程级基础设施：日志、内存分配器、信号、时间模块
2. 读取配置文件和命令行参数，构建 `ServerConfig`
3. 打开数据目录并检查运行目录完整性
4. 初始化存储引擎并执行恢复
5. 加载系统表与权限缓存
6. 启动后台线程
7. 打开网络监听套接字
8. 标记服务为 ready

## 工程实现建议

- 启动阶段必须有“阶段化失败回滚”能力，不能启动一半后让系统处于半初始化状态。
- 把后台线程启动统一交给 `BackgroundTaskManager`，不要在各模块里随手 `std::thread(...)`。
- 日志系统要在非常早的阶段就可用，否则启动失败会很难定位。
- 在恢复完成前不要接收连接，否则可能把未恢复完成的引擎暴露给前台请求。
