# 自研 MySQL 内核设计总览与设计原则

## 模块目标

本文档是这套设计文档的总入口。目标不是复刻当前仓库的所有历史包袱，而是以当前仓库为参照系，提炼一套适合 C++ / 存储方向工程师实现“接近生产可用的单机 MySQL 内核”的模块划分和落地原则。

本文档明确三件事：

- 这套设计文档覆盖哪些主线能力
- 哪些能力是单机内核必做，哪些放到扩展篇
- 如果你自己实现，需要优先遵守哪些架构原则

## 当前仓库参照实现

当前仓库是一个 Facebook MySQL 5.6 分支，单机内核主线能力主要散落在以下目录：

- `sql/`: 服务启动、连接管理、SQL 解析、优化器、执行器、权限、DDL、复制协调
- `storage/innobase/`: InnoDB 风格事务存储引擎
- `storage/perfschema/`: 观测与内部指标暴露
- `include/`, `mysys/`, `vio/`, `strings/`: 公共基础设施层
- `client/`, `libmysql/`, `sql-common/`: 协议、认证和客户端能力
- `scripts/`, `support-files/`: 系统表初始化、服务脚本与部署辅助
- `mysql-test/`, `unittest/`, `tests/`: 单元测试和集成回归体系

## 如果你自己实现，应该怎么抽象

单机 MySQL 内核建议拆成以下主线模块：

1. 进程模型与启动流程
2. 连接管理与 MySQL 协议
3. SQL 解析器与语义分析
4. 查询优化器
5. 执行器
6. 存储引擎抽象层
7. 行存储与页组织
8. 索引结构设计
9. 事务系统与 MVCC
10. 锁管理与并发控制
11. WAL 与崩溃恢复
12. DDL 与元数据管理
13. 系统表与启动初始化
14. 可观测性与运维能力
15. 测试体系与工程化

单机主线之外，单独放入扩展篇：

- Binlog
- GTID
- 主从复制
- 高可用与故障切换

这种拆法的关键点是：先把“单机正确性闭环”做完整，再做“分布式扩展”。不要在第一版把复制、高可用和共识协议压进核心事务路径。

## 核心数据结构

单机内核建议优先定义这些跨模块对象：

- `ServerContext`: 全局运行时、配置、后台线程、模块注册表
- `Session` / `THD`: 每连接上下文、事务上下文、语句执行上下文
- `Lex` / `ParseTree` / `ResolvedStmt`: 解析和语义分析产物
- `PlanNode` / `ExecNode`: 逻辑计划与物理执行节点
- `TableDef` / `ColumnDef` / `IndexDef`: 元数据定义对象
- `StorageEngine` / `TableHandle`: SQL 层对引擎的抽象接口
- `Page`, `Record`, `IndexEntry`: 存储层基本载体
- `Transaction`, `ReadView`, `UndoRecord`, `RedoRecord`: 事务与恢复基础对象
- `Lock`, `Latch`, `MDLLock`: 并发控制对象

## 关键流程

单机 MySQL 内核主路径可以抽象为：

1. 进程启动，初始化全局配置、日志、系统表和存储引擎
2. 建立网络监听，接入客户端连接并完成认证
3. 将客户端命令分发到 SQL 解析与语义分析层
4. 将已解析语句交给优化器生成物理执行计划
5. 执行器按算子树驱动存储引擎读写数据
6. 事务系统负责可见性、锁、日志和提交语义
7. WAL 与恢复系统保证崩溃后一致性
8. DDL、系统表、观测体系和测试体系支撑工程可用性

## 工程实现建议

- 第一版就把边界分清，不要把解析、优化、执行、事务和存储逻辑糊在一个对象里。
- 第一版就定义好 `Session`、`StorageEngine`、`Transaction` 这三个跨模块主对象；后面很多扩展都依赖它们的稳定边界。
- 不要一开始追求支持所有 SQL。优先支持生产上最重要的一小组语句，并把内部正确性和崩溃恢复做好。
- 第一版优先实现 InnoDB 风格的单机事务引擎能力，不要试图同时支持太多真正不同的存储模型。
- 尽量把后台线程、刷脏、checkpoint、purge、统计信息刷新等异步路径显式建模，不要把它们藏进前台请求线程里。

## 最小可用版本

接近生产可用的单机最小版本，至少应满足：

- 支持基础 MySQL 协议握手和认证
- 支持常见 DDL / DML / SELECT
- 支持 B+Tree 索引、事务、MVCC、WAL、崩溃恢复
- 支持基础权限系统和系统表初始化
- 支持错误日志、状态指标和基础诊断
- 有稳定的单元测试和 SQL 回归测试体系

## 继续演进方向

- Binlog、GTID 和复制
- Online DDL 与更细粒度元数据管理
- 更成熟的统计信息与代价模型
- 多线程并发优化、锁竞争治理、后台线程调度优化
- 热备份、逻辑备份、在线校验与更强的 observability
